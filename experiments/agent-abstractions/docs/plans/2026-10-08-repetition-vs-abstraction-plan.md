# Study 2 (repetition vs abstraction, chains) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run Claude Code and Codex over 4-step task chains on four Actual zones in two
versions (R repeated / F factored) and measure missed copies, carried defects,
efficiency, duplication growth and design quality.

**Architecture:** Reuse the study-1 harness (`aa`): variants are base + patches, images
per condition, isolated agent runs in Docker, evaluator with seeded fast-check. New:
conditions `R`/`F` (patches under `substrate/patches/study2/`), a chain task format
(`tasks2/`), a chain runner that carries the agent's tree from step to step, a chain
evaluator (per-consumer + cumulative tests, coverage, jscpd), study-2 tables.

**Tech Stack:** as study 1 (Python 3.12/uv/pytest; TS/vitest; Docker; Node 24.18.1);
plus `jscpd` (pinned) in the images.

**Spec:** `docs/specs/2026-10-08-repetition-vs-abstraction-design.md`.

## Global Constraints

- Base `9732a446`; conditions exactly `R`, `F`; study-1 conditions/results untouched.
- R/F frozen (tag `rf-frozen`) before any chain task is written; suites identical on R
  and F (seeded fast-check), typecheck 0 errors; independent refactor review before freeze.
- Existing inconsistencies preserved in F via explicit helper parameters.
- Agents: `claude-sonnet-5-5`, `gpt-6-luna`, effort medium, no web, blocked hosts,
  isolated config, same prompt template, 25 min / 60 turns per step.
- Statements never reveal copy counts or locations; leak check extended accordingly.
- Hidden tests: behavioural via handlers; only network boundary mocked; per-consumer;
  must fail on untouched R and F; never name F helpers or R copies.
- Author/implementer separation for chain tasks; implementer never gets hidden tests
  (not mounted) and its transcript is audited.
- Runs: `runs2/` (pilot `runs2-pilot/`), never mixed with study 1.
- Size: 4 zones × 2 conds × 8 chains × 4 steps per agent (256/agent) unless amended
  after the pilot, before the full run. Estimate (time + quota) given before pilot and
  before full run.
- Tables generated by script only.

## Review Focus

1. **A step whose agent leaves an unparseable tree** → the next step still starts from
   it, evaluation records `correct=false` and carried-defect tests still run. Test in Task 4.
2. **An agent that edits a hidden-test path or test infra** → restored from the pristine
   step pre-image before evaluation (as study 1). Test in Task 4.
3. **Consumer tests that pass for the wrong reason on untouched trees** → sanity requires
   each consumer test to fail individually on untouched R and F. Test in Task 2.
4. **jscpd counting test files or node_modules** → restricted to the zone's source files
   list. Test in Task 4.
5. **Chain state leaking between chains** (shared work dir) → each chain has its own
   tree dir keyed by (agent, cond, zone, chain). Test in Task 3.

### Task 1: R/F variants, refactor review, equivalence, freeze

**Files:** `substrate/patches/study2/r.patch` (Z2 helper inlined at server call sites),
`substrate/patches/study2/f.patch` (helpers for Z1–Z4 + call-site migration),
`docs/study2-variants.md` (what each helper is, preserved inconsistencies, honesty list),
`src/aa/config.py` (`CONDITIONS2 = ("R","F")`, `CONDITION_PATCHES` entries
`R: (lint-script, study2/r.patch)`, `F: (lint-script, study2/f.patch)`), CLI choices
accept R/F for `variant build|install`, `image build`, `suite baseline`, `equivalence`.

- [ ] Write `docs/study2-variants.md` from the zone table in the spec: for each zone the
  helper name/signature in F, the R form, every preserved inconsistency and the parameter
  that preserves it.
- [ ] Build R and F trees, typecheck 0 errors, full suite on both with seed: identical
  pass/fail sets (`aa equivalence R F`), and each identical to base A's baseline.
- [ ] Independent review agent (not the author) reads the R→F diff and the doc and answers
  "reasonable refactor, or straw man either way?"; fix and re-review until it passes.
- [ ] Export patches, rebuild from patches, re-run equivalence; build images
  `aa-actual:R`, `aa-actual:F` (jscpd pinned in both); commit; `git tag rf-frozen`.

### Task 2: Chain tasks (author / implementer / sanity)

**Files:** `tasks2/<zone>/chain.json` (zone, consumers list per step, step ids),
`tasks2/<zone>/T<k>/statement.md`, `tasks2/<zone>/T<k>/hidden/<test files>`,
`tasks2/<zone>/T<k>/consumers.json` (test name → consumer id), `tasks2/<zone>/T<k>/reference.{R,F}.patch`,
`tasks2/<zone>/sanity.json`, `tasks2/<zone>/provenance.json`; `src/aa/chains.py` (load,
validate, sanity).

- [ ] Assert tag `rf-frozen` exists before writing anything under `tasks2/`.
- [ ] Author agent per zone: 4 statements (behaviour only; leak check: no paths, function
  names, copy counts) + per-consumer hidden tests through handlers.
- [ ] Sanity per step on untouched R and F: **each consumer test fails individually**
  (Review Focus 3).
- [ ] Implementer agent per zone (separate, statement only, hidden tests not mounted):
  reference chain on R and on F; each step passes its own and all previous steps'
  hidden tests on its version, lint/typecheck green. Audit transcript for any hidden/ access.
- [ ] Adjudication ≤2 rounds; record in provenance; commit `tasks2/`.

### Task 3: Chain runner

**Files:** `src/aa/chain_runner.py`, tests `tests/test_chain_runner.py`.

- [ ] `run_chain(agent, cond, zone, chain_idx, runs_root)`: step 1 starts from the
  untouched variant; step k starts from step k-1's start tree + the agent's step k-1 diff
  (applied with `git apply --3way`; if it fails, from the step k-1 tree as the agent left
  it, recorded). Each step: fresh container, same isolation/flags as study 1, prompt =
  template + step statement; outputs `runs2/<agent>/<cond>/<zone>/<chain>/T<k>/`
  (`transcript.jsonl`, `diff.patch`, `pre-image.tar` or tree ref, `agent.json`).
- [ ] Unit tests with a fake agent: state carried correctly; chains isolated (Review
  Focus 5); a broken step does not stop the chain.
- [ ] Scheduler: chains in parallel, steps in series; concurrency per agent; infra retry
  rules as study 1.

### Task 4: Chain evaluator

**Files:** `src/aa/chain_eval.py`, tests `tests/test_chain_eval.py`.

- [ ] Per step, on the agent's post-step tree with pristine test infra restored (Review
  Focus 2): run step k hidden tests (per consumer) and steps 1..k-1 hidden tests;
  write `result.json` with `correct`, `consumers_passed/N`, `missed_copy`,
  `carried_defects`, lines/tokens/turns/tool calls/wall, `t2_reuses_logic` (static: new
  consumer calls the F helper / an R copy / reimplements).
- [ ] Per chain: jscpd on the zone's source file list (Review Focus 4) at start and after
  T4; cumulative diff; packet for the design review.
- [ ] Tests: unparseable tree (Review Focus 1), infra restore, coverage counting.

### Task 5: Tables and design review hook

**Files:** `src/aa/tables2.py`, `aa tables2` CLI.

- [ ] Missed-copy rate per condition × agent with Wilson CIs; mixed-effects logistic

  and carried defects; per-zone breakdown.
- [ ] Reuse the study-1 design-review packet builder with verified pre-images.
