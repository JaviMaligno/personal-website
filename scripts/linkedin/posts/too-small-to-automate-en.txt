A hundred and fifty support messages, each needing one call: billing problem or login problem. Forty markets to size with the same question, two words swapped each time. The work repeats, every row needs a judgement, and that pair is exactly why it is still being done by hand inside a chat window, one message at a time.

Almost nobody automates it. Not because it's hard.

The problem is what you're asked to build in exchange. The moment you want to stop pasting rows by hand, every exit walks you out of the chat and hands you a product to build: a provider account with a bill metered by the token, a prompt that now has to be tested call by paid call with no green tick at the end, and an interface for whoever has to read a hundred and fifty answers.

That's a product. To send messages in a chat.

Writing the loop was never the cost. A coding agent writes the twenty lines faster than you can specify them. The three costs above survive that untouched, and not one of them is code.

So I built the thing that stays inside the chat. Prompt Scripter takes one prompt with placeholders and a list of rows, and sends one message per row into the ChatGPT, Claude or Gemini conversation you already have open. Same model, same project, same memory, on the subscription you already pay for. The answers arrive in the thread, where you were reading them anyway.

The template comes from a message you already sent: the prompt you spent six rounds getting right is sitting in the thread, and a button turns it into the template.

The script is still right when the job runs forever on a schedule, when the output feeds a system rather than a person, or when the judgement turns out to be a rule nobody wrote down. The article goes through where that line sits.

If the disproportion isn't real, neither is the tool, and I'd rather be told.
