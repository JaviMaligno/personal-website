Matt Pocock argues we should design more abstractions for coding agents and back them with harsh lint. I tested the next question: if the code is already repeated, can the agent be the one who designs the abstraction?

384 chains of four tasks on a real codebase (Actual's loot-core), three agents (Claude Sonnet, Claude Haiku, Codex with GPT-6 Luna), three levers: a "do not copy logic" rule in AGENTS.md, a duplication lint that fails on new clones, or a step zero asking the agent to make the logic live in one place.

The rule and the lint helped one agent out of three. Asking for the refactor helped all three.

What the refactor bought was mostly search. With no lever, Codex missed a copy in 33% of rule changes: it consolidated the copies its grep found and stopped. After its own refactor it missed 12%, fewer than with code a human had factored.

Under the lint, Codex added jscpd:ignore and stretched another provider's function with flags. The duplication count went down and the judged design didn't move.

If you want the abstraction, ask for it as a task, and name the exceptions that must survive.
